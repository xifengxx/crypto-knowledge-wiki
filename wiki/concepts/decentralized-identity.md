# 去中心化身份（Decentralized Identity / DID）

## 一句话定义
不依赖中心化机构管理，由个人/实体自主创建、拥有和控制其数字身份的体系。核心构建模块为去中心化标识符（DID）和可验证凭证（VC）。

## 核心原理

### DID 的四大属性
1. **去中心化**：不依赖中心化机构创建，实体可随心所欲创建，在不同环境下保持身份、角色和互动的分离
2. **持续性**：一旦创建，永久分配给实体（部分 DID 设计为短暂身份）
3. **可解析**：可用来揭示关于实体的额外信息
4. **可验证**：实体可通过加密签名证明 DID 所有权或相关声明，不依赖第三方

### DID 的四部分结构（W3C 标准）
- **方案**：前缀 `did:` 告诉系统这是 DID 而非其他标识符
- **DID 方法**：指定如何解释该标识符（W3C 登记了 100+ 种方法），每种关联自己的 VDR
- **唯一标识符**：方法特定的唯一 ID（如特定区块链上的地址）
- **DID 文件**：包含实体自我认证方式、属性/声明、服务端点指针

### Web3 身份堆栈（七层架构，自下而上）
1. **可验证数据注册处**（VDR）：区块链作为 DID 发布层（如 did:pkh、Fractal、Kilt、Dock）
2. **去中心化数据存储**：Arweave（永久存储）、IPFS/Filecoin/Crust（基于合约的持久性）
3. **数据变更和可组合性**：Ceramic（数据流+DID 验证更新）、Tableland（NFT 表+SQL 查询）
4. **钱包**：密钥管理 + 身份钱包（ONTO、Nuggets、Polygon ID Wallet）vs 加密钱包
5. **认证**：Sign-In with Ethereum (SIWE)、Peer DID（每服务/互动使用唯一标识符防止关联追踪）
6. **授权和访问控制**：Lit Protocol（MPC 密钥管理+链上条件解密）、Kepler（用户控制数据库 Orbits）、CACAO（链不可知对象能力）
7. **证明和凭证**：可验证凭证（VC）、NFT 徽章、Orange Protocol（声誉模型聚合）

### 灵魂绑定代币（SBT）

灵魂绑定代币（Soulbound Token, SBT）是去中心化身份中的关键组件，由 Vitalik Buterin 在 2022 年 5 月的论文《Decentralized Society: Finding Web3's Soul》中正式提出。

**核心特性**：
- **不可转移**：与钱包地址绑定，无法交易或转让，区别于传统的 ERC-721 NFT
- **关系证明而非权威证明**：一枚 SBT 仅证明某地址参与过某事件，真正的身份画像需要大量 SBT 的长期积累
- **数据积累驱动**：随着时间推移，大量多样化的 SBT 积累形成不可伪造的链上身份画像——单一事件可伪造，但复杂多维的特征难以复制

**SBT 应用方向**（基于 ArkStream Capital 2022 年分析）：
- **链上信用积分**：通过 SBT 积累的链上行为数据构建信用评分，用于无抵押/低抵押小额借贷
- **替代部分 KYC**：低安全级别场景（如空投、白名单）可通过 SBT 验证深度参与者，高安全场景（如借贷）仍需传统 KYC + SBT 辅助
- **钱包社交找回**：通过 SBT 建立的社交关系，多人交叉验证后可找回丢失的钱包
- **DAO 贡献量化**：将成员的 Discord 活动、Github 贡献、论坛问答等转换为链上可验证 SBT

**CGV Research对SBT的三类应用场景归纳（2022）**：
1. **抵押不足贷款**：通过可证明的声誉系统（SBT链上行为积累），解决借贷市场个人难以获得非足额抵押贷款的问题
2. **DAO女巫攻击防御**：通过检查投票持有的SBT之间的相关性，检测和防止个人/群体积累大量治理代币并操纵投票
3. **社交钱包恢复**：通过朋友、家人和其他联系人等社交关系，在丢失钱包密钥时将控制权转移到新密钥

此外，SBT在空投机制优化、GameFi等级/战绩/特殊技能绑定等场景也大有可为。CGV认为SBT的最终目标是将现实社会结构（家庭、教堂、团队、公司等）带入Web3，而不仅仅是金融系统（DeFi）。参见 [[来源_2022-07_加密牛市_十大叙事_CGV]]。

**当前挑战**：
- 数据格式不统一，缺乏通用协议标准（EIP-4973、EIP-6114、ERC721S 各自为政）
- 缺乏时间维度的协议开发——靠积累量变到质变的数据才是 SBT 的关键
- 信息预处理和分级机制缺失——无法有效过滤有用数据
- 存储问题——去中心化存储低效昂贵，混合存储（如 Farcaster 的半中心化方案）可能是妥协方向

**可编辑隐私**：SBT 场景下的隐私有三个层级——access（是否可访问）、editing（是否可编辑）、cashflow（是否能被用于盈利），三者应分开对待并分级收费。隐私不是免费的，而是明码标价的"奢侈品"。参见 [[来源_2022-09_灵魂绑定代币_SBT_ArkStream]]。

### DIF 四层身份模型（2021 年 Amber Group 分类）

Amber Group 在 2021 年的报告中采用 DIF（去中心化身份基金会）的 4 层身份模型对 DID 项目进行分类（比后续的七层堆栈更粗粒度）：

1. **第 1 层：标识符和标准** — 标准、标识符和命名空间创建公共信任层。核心参与者为 [[DIF]]（去中心化身份基金会）
2. **第 2 层：基础设施** — 通信、存储和密钥管理。代表项目：[[ceramic]]（数据流）、[[ens]]（域名到 DID 的映射）
3. **第 3 层：凭证** — 凭证的创建、管理和交换。代表项目：[[brightid]]（社交身份网络，30,000+ 用户、抗女巫攻击）
4. **第 4 层：应用程序、钱包和产品** — 面向消费者的实际用例。代表项目：[[goldfinch]]（无抵押贷款）、[[truefi]]（链上信用评分）、[[Gitcoin]]（公共产品资金）、Ethsign（去中心化电子协议）

**横向影响因素**：GDPR 等法规在所有层级产生影响。

该模型与后出现的七层身份堆栈（VDR→数据存储→数据变更→钱包→认证→授权→凭证）相比更侧重项目分类而非技术分层，但都强调 [[metamask]] 作为"Web3 浏览器式网关"的关键抓手地位。参见 [[来源_2021-11_去中心化身份_DID_通行证_AmberGroup]]。

### 三层身份架构（用户视角）

2022年由不确定思维在《去中心化身份终局之战》中提出的另一种分类框架，从用户体验和资产管理角度将去中心化身份分为三层：

1. **外显身份（Manifest Identity）**：一系列凭证、标识、行为、关系、声誉的集合。包括ENS/Lens等命名服务、POAP/Galxe/RabbitHole等行为轨迹、SBT灵魂绑定代币、社交关系和信誉证明。作用是方便外部关系对身份进行标识。
2. **代理身份（Proxy Identity）**：一系列功能专属的账户，如社交账户、游戏账户、交易账户、DeFi账户、匿名账户等。各账户拥有独立用途和安全边界，可以由主权账户控制的合约账户实现，在发生危险时使用主权账户重置密钥。实现风险隔离。
3. **主权身份（Sovereign Identity）**：Web3最重要的基础——个人资产神圣不可侵犯的保障。密钥就是主权身份，宣誓一切自己可控。个人使用到硬件钱包已相对安全，组织/社区可采用多签（如Gnosis Safe）。在未来架构中，主权身份是最不常用的身份，仅在创建代理身份时授权，或在代理身份存在风险时重置密钥。

该架构与DID/VC七层技术堆栈互补：技术堆栈回答"如何实现"，三层架构回答"为何设计"。参见 [[来源_2022-07_去中心化身份三层架构_DID_Mirror]]。

### 隐私基元
- **zk-proofs**提供四种隐私保护：抗关联性（每次出示唯一证明）、选择性披露（只分享必要属性）、复合证明（合并多个 VC）、预测（证明阈值而不泄露具体值）
- **BBS 签名方案**（MATTR 2020 提出）：允许选择性披露 + 零知识证明消除关联来源

## 为什么重要
- 解决 Web2 身份的核心问题：身份碎片化、被少数利益相关方控制、权力不对称
- Crypto 作为"特洛伊木马"：代币激励机制将去中心化身份从隐私技术专家扩散到数亿用户
- 将应用与数据层解耦，实现数据民主化——用户可将内容/社交图/声誉跨平台移植，应用开发起点不再为空
- ZK 技术使身份系统能在"可公开验证"与"保护隐私"之间取得平衡

## KYA：Know Your Agent——Agent 时代身份验证的新要求

2025-2026 年 AI Agent 支付基础设施的爆发催生了身份验证的新需求：**KYA（Know Your Agent）**——Agent 支付安全的核心瓶颈，也是 DID 在 Agent 时代的新应用场景。

### 为什么需要 KYA
Agent 能花钱了，但谁该为 Agent 花错的钱负责？Step Finance 攻击（26 万枚 SOL 约 3000 万美元被转走）和 LLM 路由器攻击（50 万美元钱包被盗）证明，没有身份验证的 Agent 支付只能停留在每笔几分钱的 API 微支付。核心问题：确认一个 Agent 是谁派出来的？它被授权做什么？授权的边界在哪里？

### 四条 KYA 路径并行赛跑

| 路径 | 代表方案 | 核心方法 | 优势 |
|------|---------|---------|------|
| **生物识别** | World（前 Worldcoin）AgentKit | 虹膜验证 → World ID → zk 委托给 Agent → 证明背后是真人 | 反女巫攻击强，近 1800 万用户 |
| **KYA 协议** | Skyfire + Experian | 给 Agent 签发 JWT 令牌（记载构建者、授权者、权限、支付方式）。Experian 发布 Agent Trust 框架，Cloudflare 做网络边缘验证 | 信用评分+身份凭证整合 |
| **卡组织延伸** | Visa TAP / Mastercard Verifiable Intent | 密码学签名给 Agent 发凭证，把身份/指令/交易结果打包成防篡改记录 | 直接利用现有信用卡信任网络 |
| **链上去中心化身份** | [[erc-8004]] | 每个 Agent 被铸造为 ERC-721 NFT，从 337 个注册增长到约 13 万个 | 链原生的可组合身份层 |

四条路各切一个层面，目前没有任何一条能独立解决全部问题。银行业已将 KYA 视为 KYC 在 Agent 时代的自然延伸。

ERC-8004 是其中唯一纯链上的方案，设计包含三个链上注册表：
1. **身份注册表（Identity Registry）**：每个 Agent 获得 ERC-721 NFT 作为身份，指向标准化 Agent 卡片
2. **声誉注册表（Reputation Registry）**：结构化反馈 + x402 支付证明，所有信号公开可查询
3. **验证注册表（Validation Registry）**：TEE 预言机/zkML/质押担保等第三方密码学验证

ERC-8004 于 2025 年 8 月 13 日提交 EIP-8004，由以太坊基金会 dAI 团队负责人 Davide Crapis、MetaMask 的 Marco De Rossi 和 Jordan Ellis（与 Google A2A 团队相关）联合提出。2025 年 10 月最终版本发布，签署方包括 Coinbase 的 Erik Reppel（x402 创建者）。详见 [[来源_2025-10_ERC-8004_AI_Agent_信任层_深潮]]。

详见 [[来源_2026-05_AI_Agent_支付狂飙十二个月]]、[[x402]]、[[visa]]、[[mastercard]]、[[worldcoin]]。

## ERC-3643 / OnchainID：DID 在合规代币化中的实际应用

OnchainID 是 [[tokeny-solutions]] 开发的身份框架，是 ERC-3643（合规代币标准）的核心身份组件。ERC-3643 在每次代币转账时实时验证发送方和接收方的 OnchainID 状态——DID 从"用户可选组件"升级为"代币核心基础设施"。

OnchainID 发行和管理去中心化身份（DID），可存储来自 KYC 提供商等受信方的加密声明，在保护持有人敏感个人信息的同时确保可验证合规。这种"声明（claim）链上身份系统"是合规代币化最关键的隐私-合规平衡机制。

详见 [[来源_2025-04_ERC-3643_证券代币标准_Chainalysis]]。

## 我的立场
去中心化身份堆栈在基础设施层面已经完备，但应用层采用严重滞后。站在 2026 年看，2022 年预测的"统一凭证聚合层"并未出现，Web3 身份仍高度碎片化。密钥管理的 UX 摩擦仍是最大瓶颈。但方向无疑是正确的——当数据民主化的 UX 门槛真正降低时，这将成为 Web3 最大的 mass adoption 催化剂之一。值得关注的是 MPC 钱包的消费者化进展和 ZK 技术在身份场景的实际部署。
